# An analysis of the current state of the repository
This branch is currently not fit for upstream merge, but includes many extensions and added functionality. 
Most of the functionality that was added was made using codex as a curiosity to see how well they do on this repo.
As such, this repository should be regarded as highly experimental.

### The good
In short, compared to the main branch, the segment_codex branch included these improvements:

1. Added multi output handling: The mian branch handles straightforward neural networks for image classifications which have a single input and output. The current repository can handle multiple outputs, but does **not** handle multiple inputs
2. mask support: Masks can be added to the forward/backward path as a separate argument in forward and backward during streaming. This allows users to track mask gradients and filter out pixels at arbitrary places in their networks
3. Reducer support: Reducers are special cases where tiles get reduced to a single number at the **end** of the network. In the main branch, outputs were [1,C,H,W] tiles. Reducers allow for more flexibility, and even allow for global operations to be used, e.g. global average/max pooling, attention pooling, etc, and help save further memory. 
   1. Reducers will allow many models to be end-to-end streamable. For example, a ResNet architecture in the main branch is not fully streamable end-to-end due to global average pooling, but this is possible using reducers in this branch
5. Upsampling layer (align_corners=False) is added, which opens the door to segmentation or localization networks.
6. Several grad compare examples under the examples folder for slightly easier debugging

### Future points of improvements

1. A better API design for reducers. Current design is still very hands-on and requires extensive knowledge of how streaming works
2. Break up scnn into smaller files/modules with better explanations, variable-naming, and API endpoints for e.g. reducers and new layers. I think this requires building a better or entirely new engine that performs streaming at the most basic level.
3. Proper unit testing. Most of these are old or auto-generated by Codex. 
   1. Follow the guidelines in examples/grad_compare files, since they measure streaming equivalency to non-streaming models.
   2. Add modules to test reducers specifically.
   3. Add actual examples instead of current grad compare examples.
4. Add new and better documentation. 
   1. Proper streaming explanation
   2. Recommended hardware and pytorch version
   3. Basic streaming model tutorial
   4. Whcih layers are not streamable and should be frozen/removed
   5. API endpoint design and adding custom modules and registering them
